# 03 第 3 级：多用户服务系统

这一级做完，Cinux 能当服务器和多人用的机器。非特权用户能经 SSH 登录，服务能开机启动、写日志、崩溃后自己恢复，数据和磁盘断电之后还可信。

进入条件：[《原生开发工作站》](./02-workstation.md)的检查全部通过。

## 这一级要达到的行为

- 能做：非特权用户登录，服务按依赖启动，日志轮转，地址、路由、DNS、校时和证书按配置工作，ext4 数据盘可写可恢复。
- 必须失败得对：用户不能读另一个用户的私有文件，不能 kill 或 ptrace 别人的进程，服务不能恢复已经放弃的权限，崩溃循环有退避，端口、日志盘满、断网和资源超额不拖垮别的服务，PID 回收不会误杀新进程。
- 不能据此宣称：自己的 supervisor 等于兼容 systemd。那要在《选定发行版的用户态》单独验。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **扩展属性接口**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「完整文件元数据」、[《可信命令行》](./01-shell.md)的「创建、umask 和改属性」）：先实现目标后端的 xattr 名称空间、大小和权限，不支持后端明确拒绝。验收：普通用户不能伪造 security 属性提权，设置/替换/删除 flags 与满盘错误正确。
- [ ] **可信随机数**（内核机制、用户态库，前置[《可信命令行》](./01-shell.md)的「资源上限的失败行为约定」）：定义熵源、启动就绪、阻塞/非阻塞与重启状态，审查 getrandom/随机设备。验收：不能用可预测计时填充后宣称安全，熵未就绪的行为可测，用户指针与 flags 有拒绝用例。
- [ ] **交换槽与换出**（内核机制，前置[《原生开发工作站》](./02-workstation.md)的「可控缓存回收」、[《原生开发工作站》](./02-workstation.md)的「块 I/O 故障与持久化顺序」）：先用受控交换分区管理槽、引用和写出状态，不把任意文件直接当可靠 swap。验收：可验证页面写到独立槽，失败保留原页，不提前释放仍被访问的帧。
- [ ] **文件变化通知**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「链接与目录重命名」、[《原生开发工作站》](./02-workstation.md)的「epoll 的完整目标语义」）：实现选定 inotify 事件、rename 配对、监视失效与溢出。验收：编辑器原子保存能被观察，队列满显式报告，不拿丢事件冒充完整通知。
- [ ] **ext4 特性识别**（内核机制，前置[《原生开发工作站》](./02-workstation.md)的「全链路大偏移」、[《原生开发工作站》](./02-workstation.md)的「块 I/O 故障与持久化顺序」）：固定支持的块大小、64 位描述、extent、目录与校验和组合。验收：用 Linux 生成的测试卷分类，未知不兼容位拒绝，不悄悄改盘。
- [ ] **多 GiB 文件与长期开发卷**（内核机制、测试与证据，前置[《原生开发工作站》](./02-workstation.md)的「跨越现有单文件限制」、[《原生开发工作站》](./02-workstation.md)的「块 I/O 故障与持久化顺序」、[《原生开发工作站》](./02-workstation.md)的「文件/目录同步约定」）：接完整大小字段与所需间接寻址，完成更大容量验证。验收：32–64 GiB 卷和超过 4 GiB 的非空文件可随机读写、同步、重启校验。可选已通过的 ext2 或 ext4 后端，所用后端结果分别记。
- [ ] **接口、地址和路由配置**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「明确 ABI 与公共模块边界」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：取消只能使用固定地址的假设，先提供受控配置接口。验收：切换地址/默认路由可通信，非法配置被拒绝，普通用户无权改全局网络。
- [ ] **套接字通用行为**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」、[《可信命令行》](./01-shell.md)的「poll/select 的原子等待」）：复核非阻塞 connect/accept、shutdown、错误、超时和常用选项。验收：客户端断开/拒绝/半关闭与 poll 结果符合对照，不忙等。基线实测开发用户执行 iputils `ping` 报 permission denied，而 `SOCK_DGRAM` 的 ICMP socket 能创建，官方 `test_native_build.py` 也卡在这一步，要找出两条路径的差异并让普通用户 ping 与参考行为一致。
- [ ] **日志服务**（用户态组件，前置[《原生开发工作站》](./02-workstation.md)的「服务生命周期最小版本」、[《原生开发工作站》](./02-workstation.md)的「文件/目录同步约定」）：接收标准输出/错误与结构化消息，限制容量和轮转。验收：服务退出仍有日志，磁盘满不反压到全系统死锁，秘密访问受限。
- [ ] **服务依赖与配置授权**（用户态组件，前置[《原生开发工作站》](./02-workstation.md)的「服务生命周期最小版本」、[《原生开发工作站》](./02-workstation.md)的「登录认证与降权」）：在单服务可用后接依赖顺序、就绪/失败传播、运行身份和控制端鉴权。验收：循环依赖/坏配置拒绝，普通用户不能改系统服务身份或启动策略。
- [ ] **设备模型接口封口**（内核机制，前置[《可信命令行》](./01-shell.md)的「明确 ABI 与公共模块边界」）：复核枚举、能力、引用与字符/块/网络设备面。验收：设备能由同一来源列出，重复注册/探测失败有明确结果，不污染上层服务状态。
- [ ] **应用/服务资源组**（内核机制，前置[《可信命令行》](./01-shell.md)的「生命周期与退出取消」、[《原生开发工作站》](./02-workstation.md)的「CPU 与时间统计」、[《原生开发工作站》](./02-workstation.md)的「内存与 I/O 统计」、[《原生开发工作站》](./02-workstation.md)的「OOM 与保留资源」）：定义不可凭 setsid/改父进程逃离的成员继承和组寿命。验收：父/子/孙与多线程正确归组，管理者退出按定义处理。

### 第 2 步

- [ ] **ACL 与文件能力**（内核机制、Linux 接口、用户态组件，前置「扩展属性接口」、[《可信命令行》](./01-shell.md)的「特殊权限位」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：在普通 mode 权限正确后接目标 POSIX ACL 和文件 capability，工具/策略在用户态。验收：ACL mask/继承与 exec 能力授予符合目标行为，非授权属性写入不提升权限。
- [ ] **换入与并发取消**（内核机制，前置「交换槽与换出」、[《原生开发工作站》](./02-workstation.md)的「VMA 与映射生命周期」）：缺页换入、共享/COW 引用、并发退出和 I/O 错误统一处理。验收：工作集超过 RAM 仍内容正确，同页并发缺页不重复破坏，进程退出可回收交换槽。
- [ ] **设备和系统状态视图**（内核机制、Linux 接口，前置「设备模型接口封口」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：按目标工具补 sysfs/proc/sys 的真实属性与受控写入。验收：枚举来自设备注册表，未支持属性明确缺失，普通用户不能借属性写入取得特权。
- [ ] **ext4 干净卷只读**（内核机制，前置「ext4 特性识别」、[《原生开发工作站》](./02-workstation.md)的「通用挂载生命周期」）：实现 extent 树和目录遍历到读取。验收：跨层 extent/大文件哈希一致，坏校验/越界被拒绝，需要日志恢复的卷不能当干净卷使用。
- [ ] **TCP 容量与压力恢复**（内核机制，前置「套接字通用行为」、[《可信命令行》](./01-shell.md)的「资源上限的失败行为约定」）：扩展连接、监听与缓冲的分配策略，保留已有重传/乱序能力。验收：多于当前 8 连接的受控压力可服务或可预测拒绝，连接回收后继续接收。
- [ ] **DHCP 与网络配置服务**（用户态组件，前置「接口、地址和路由配置」、「套接字通用行为」）：租约选择/更新、链路变化和配置持久化在用户态。验收：取得/续租/失租后状态正确，静态配置仍可用，服务退出不破坏内核网络对象。
- [ ] **socket 激活与平滑重启**（用户态组件，前置「服务依赖与配置授权」、[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」、[《原生开发工作站》](./02-workstation.md)的「SCM_RIGHTS 描述符传递」）：用户态保留监听 FD 并按明确协议交给服务，配停止/重启超时。验收：重启不误关闭其他服务 FD，错误继承被拒绝，旧进程可回收。
- [ ] **MBR/GPT 分区与块节点**（内核机制，前置「设备模型接口封口」、[《原生开发工作站》](./02-workstation.md)的「块 I/O 故障与持久化顺序」）：保留现有 MBR，增加 GPT 校验和边界检查及可用块设备节点。验收：多个分区读写互不越界，损坏分区表不越界解析。
- [ ] **固件与电源基本路径**（内核机制，前置[《可信命令行》](./01-shell.md)的「明确 ABI 与公共模块边界」、「设备模型接口封口」）：补受控 reboot 和 ACPI 电源行为，架构相关代码留在平台后端。验收：已有启动不退化，受支持平台可关机/重启。不把 UEFI 启动列为正常关机的前置。
- [ ] **单进程限额执行**（内核机制、Linux 接口，前置「应用/服务资源组」、[《原生开发工作站》](./02-workstation.md)的「公平调度与 CPU 归属」、[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」）：先验证已有 NOFILE/stack，再分别接 AS/CPU 等目标 rlimit，保持 Linux 规定的统计范围。验收：低 AS 拒绝映射、CPU 时间超限按规则通知，不能把保存 prlimit 数值当执行。
- [ ] **资源组任务数控制**（内核机制，前置「应用/服务资源组」）：在创建任务时原子计数并执行上限，退出后归还。验收：fork/线程并发不越限，setsid/reparent 不能脱离，组外任务仍能创建。
- [ ] **资源组内存控制**（内核机制，前置「应用/服务资源组」、[《原生开发工作站》](./02-workstation.md)的「OOM 与保留资源」）：定义共享页/COW/缓存算到哪个组与层级上限，接分配、回收和组内 OOM。验收：一个组耗尽时不误杀组外任务，释放后额度恢复，不能通过换父进程让统计漏掉自己。
- [ ] **资源组 CPU 控制**（内核机制，前置「应用/服务资源组」、[《原生开发工作站》](./02-workstation.md)的「公平调度与 CPU 归属」、[《原生开发工作站》](./02-workstation.md)的「CPU 与时间统计」）：先权重，再配额/周期和限流唤醒。验收：忙循环真实限速、空闲额度不伪造使用量，多核/迁移不重复累计。

### 第 3 步

- [ ] **JBD2 日志读取与重放**（内核机制，前置「ext4 干净卷只读」）：先完成已提交事务识别、校验与恢复规则。验收：受控中断的测试卷可按规则恢复，未提交事务不被当提交，不能重放时明确拒绝。
- [ ] **FAT32 交换卷**（内核机制、用户态组件，前置[《原生开发工作站》](./02-workstation.md)的「块 I/O 故障与持久化顺序」、「MBR/GPT 分区与块节点」）：实现适合 SD/U 盘交换的独立后端，和系统权限模型明确区分。验收：与参考系统互读写、长文件名和满盘错误正确，不能把 FAT 权限展示当真实 Unix 持久权限。
- [ ] **DNS 与解析器策略**（用户态组件、用户态库，前置「套接字通用行为」、「DHCP 与网络配置服务」）：覆盖 UDP/TCP DNS、搜索域、超时和结果处理，保留静态配置入口。验收：截断回退、域名不存在、断网和多地址结果可区分，不假定只能 DNS over TCP。
- [ ] **Linux 网络管理接口**（内核机制、Linux 接口，前置「接口、地址和路由配置」、「设备和系统状态视图」）：按固定 iproute2/设备服务需要补 ioctl/rtnetlink 和事件。验收：查询/变更/通知一致，错误消息不造成部分成功，不为每个管理程序另造接口。
- [ ] **设备策略服务**（用户态组件，前置「设备和系统状态视图」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」、[《原生开发工作站》](./02-workstation.md)的「服务生命周期最小版本」）：设备发现策略、命名/权限和热插拔处理在用户态，复用内核设备事件。验收：拔插时更新节点/权限，策略服务重启后可重新枚举。
- [ ] **正常关机、重启和维护**（用户态组件、内核机制，前置[《原生开发工作站》](./02-workstation.md)的「服务生命周期最小版本」、[《原生开发工作站》](./02-workstation.md)的「文件/目录同步约定」、「固件与电源基本路径」）：用户态按依赖停止服务与卸载，内核执行受权同步/电源操作。验收：关机/重启后数据保持，停止超时有边界，设备错误能进入维护路径。

### 第 4 步

- [ ] **JBD2 事务生成与提交**（内核机制，前置「JBD2 日志读取与重放」、[《原生开发工作站》](./02-workstation.md)的「文件/目录同步约定」）：单独实现日志写入、commit/flush 次序、checkpoint/revoke 和失败回退。验收：生成的受控事务能由 Linux 重放，提交各边界中断结果正确，不能把会重放等同会安全写日志。
- [ ] **IPv6 基础网络**（内核机制、Linux 接口、用户态组件，前置「接口、地址和路由配置」、「TCP 容量与压力恢复」、「DNS 与解析器策略」）：逐步实现 IPv6 socket、邻居发现、地址与路由，用户态配置配套。验收：IPv4/IPv6 loopback、局域网络和 DNS 多地址回退分别通过。
- [ ] **校时与时区**（用户态组件、内核机制、Linux 接口，前置[《原生开发工作站》](./02-workstation.md)的「时钟与 timerfd」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」、「DNS 与解析器策略」）：用户态做 NTP/时区策略，内核提供受权实时时钟调整。验收：错误系统时钟可修正，单调钟不倒退，普通用户不能修改全局时间。
- [ ] **信任库与安全更新**（用户态组件、用户态库，前置「可信随机数」、[《原生开发工作站》](./02-workstation.md)的「软件包与文件归属」、「DNS 与解析器策略」）：安装证书/仓库公钥并定义更新和撤销路径。验收：坏签名和未知来源被拒绝，离线更新也校验，信任材料不写进内核常量表。

### 第 5 步

- [ ] **ext4 已分配块覆盖写**（内核机制，前置「JBD2 事务生成与提交」）：只先开放现有文件范围内的写入和相应元数据更新，未开放操作在改盘前拒绝。验收：覆盖写/同步/中断恢复与 Linux 对照，文件尺寸和分配关系不被误改。
- [ ] **HTTPS 与远程访问**（用户态组件、用户态库，前置「DNS 与解析器策略」、「可信随机数」、「校时与时区」、「信任库与安全更新」）：移植选定 TLS/HTTP/SSH 工具并正确装载证书。验收：合法证书通过，错误主机名/过期/未知签发者失败，不靠跳过验证完成联网。
- [ ] **防火墙与访问策略**（内核机制、用户态组件，前置「套接字通用行为」、「IPv6 基础网络」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：用户态组织规则，内核在受控路径执行，先明确的入站/出站范围。验收：禁止流量确实被拦截，既有连接和规则更新行为可解释，不能只在服务 UI 隐藏端口。

### 第 6 步

- [ ] **ext4 分配与文件扩展**（内核机制，前置「ext4 已分配块覆盖写」）：增加数据/元数据块分配、extent 扩展及失败清理。验收：跨 extent 层扩展后可被 Linux 读取，满盘/事务失败不泄漏或重复分配。

### 第 7 步

- [ ] **ext4 创建文件和目录**（内核机制，前置「ext4 分配与文件扩展」、[《可信命令行》](./01-shell.md)的「链接与目录重命名」）：接 inode 分配、目录项、链接计数和事务。验收：分别测试建文件、建目录、链接及每一步中断，恢复后目录树一致。

### 第 8 步

- [ ] **ext4 截断、删除与回收**（内核机制，前置「ext4 创建文件和目录」、[《可信命令行》](./01-shell.md)的「打开后删除的寿命」）：接块回收、打开后删除和对应恢复记录。验收：最后引用前不回收，截断/删除中断后无重复块或孤儿泄漏。

### 第 9 步

- [ ] **ext4 重命名事务**（内核机制，前置「ext4 截断、删除与回收」、[《可信命令行》](./01-shell.md)的「链接与目录重命名」）：单独接跨目录 rename、替换和父子/链接变化。验收：中断后处于允许的旧/新状态，目录不会循环，不丢已承诺同步的条目。

### 第 10 步

- [ ] **写回与异常停机恢复**（内核机制、测试与证据、用户态组件，前置「ext4 重命名事务」、[《原生开发工作站》](./02-workstation.md)的「可写共享、脏页与同步」）：固定提交/刷新/写回次序，配用户态检查工具。验收：在多个更新边界强制中断，恢复后无悬挂元数据，已承诺同步的数据符合约定。

### 第 11 步

- [ ] **ext4 根盘与维护模式**（内核机制、用户态组件，前置「写回与异常停机恢复」、「正常关机、重启和维护」）：先让数据盘通过，再接根盘选择、启动与离线维护。验收：正常启动/关机/重启及受损卷进入可诊断维护路径，保留 ext2 回退启动方式。
- [ ] **升级事务和回滚**（用户态组件，前置[《原生开发工作站》](./02-workstation.md)的「软件包与文件归属」、「写回与异常停机恢复」）：把准备、切换、配置与恢复分离，记录用户配置差异。验收：写盘中断/脚本失败后可恢复旧可用版本，不能只恢复一个可执行文件就宣称系统回滚。

## 说明

- ext4 是正式的存储目标。日志保护的是文件系统更新的一致性，应用内容是否已经保存，仍然要靠正确的同步写和设备刷新。它不阻塞前面的通用文件语义。
- DHCP、DNS、NTP、TLS 和证书在用户态。内核只提供协议、权限检查和受权的时钟调整。
- 资源组、单进程限额和进程数、内存、CPU 控制器在这里先立起来。《独立桌面》的应用沙箱和《容器运行环境》都建在它上面。

## 通过这一级的检查

- [ ] SSH 以非特权用户登录，一个固定的 HTTP 服务以该身份运行，开机启动、就绪通知、日志轮转、失败退避和平滑停止都成立。
- [ ] 两个用户互相访问私有文件、互发信号、互相调试都被拒绝。
- [ ] 服务停止之后没有子孙进程遗留，资源组超额只影响组内任务。
- [ ] 断网、磁盘满、写盘失败各自发生时，别的服务照常工作，错误能被看到。
- [ ] ext4 数据盘和 Linux 交叉读写，超过 4 GiB 的文件随机读写一致，在多个更新边界强制中断后恢复，没有悬挂的元数据。
- [ ] 错误证书、过期证书、未知签发者都失败，校时之后单调钟不倒退。
