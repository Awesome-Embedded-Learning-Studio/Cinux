# 10 运行 Windows 程序

让 Windows 的程序在 Cinux 上原生运行。真实软件优先走 Wine，自研的 PE64 子集只作为受控的教学和接口实验，不同时扩大两套兼容层。

进入条件：受控 PE64 实验在《原生开发工作站》的内存和《可信命令行》的 exec 之后可以开始。Wine 要等《原生开发工作站》的描述符传递、信号上下文、共享映射和离线软件包，图形程序再等《独立桌面》。

## 要达到的行为

- 能做：一个自带许可的 PE64 命令行样本在 Wine 下运行，再接一个明确版本的 Win32 图形程序。
- 必须失败得对：畸形映像被拒绝，异常退出可回收，不被当成任意 exe 都能运行。
- 不能据此宣称：Windows 驱动、.NET、DirectX、带反作弊的游戏可以运行，或者 Ubuntu 虚拟机里的 Wine 算原生兼容。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **受控 PE64 装载实验**（用户态组件、用户态库，前置[《可信命令行》](./01-shell.md)的「exec 与线程边界」、[《原生开发工作站》](./02-workstation.md)的「VMA 与映射生命周期」）：可选教学分支，先无 CRT 样本，检查节映射、重定位、导入和 x64 ABI。验收：非首选基址也正确，畸形映像拒绝，不把 SysV 函数地址直接当 Win64 API。
- [ ] **Wine 平台依赖验证**（用户态组件、用户态库，前置[《原生开发工作站》](./02-workstation.md)的「UNIX 套接字身份与名字」、[《可信命令行》](./01-shell.md)的「标准信号帧与备用栈」、[《原生开发工作站》](./02-workstation.md)的「memfd 与 POSIX 共享对象」）：固定 64 位 Wine，测 wineserver IPC、完整信号上下文和共享映射。验收：独立探针均通过，缺口不藏在 configure 成功背后。

### 第 2 步

- [ ] **最小控制台白名单**（用户态组件、用户态库，前置「受控 PE64 装载实验」、[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」）：从 GetStdHandle/WriteFile/ExitProcess 到受控文件复制，逐项补错误码。验收：只宣称样本和 API 白名单，不推广到通用 exe/.NET/GUI/驱动。
- [ ] **原生 Wine 控制台**（用户态组件、用户态库，前置「Wine 平台依赖验证」、[《独立桌面》](./04-desktop.md)的「稳定进程引用与回收」、[《原生开发工作站》](./02-workstation.md)的「软件包与文件归属」）：prefix 初始化、进程启动、同步和退出，使用同一受控 PE64 样本。验收：异常退出可回收，不能用 Ubuntu 虚拟机里的 Wine 结果冒充。

### 第 3 步

- [ ] **Wine 图形与目标应用**（用户态组件、用户态库，前置「原生 Wine 控制台」、[《独立桌面》](./04-desktop.md)的「Vesper 与标准平台连接」、[《独立桌面》](./04-desktop.md)的「字体与中文输入」、[《独立桌面》](./04-desktop.md)的「剪贴板、拖放和文件选择」）：选择一个显示/输入后端和一个明确版本的 Win32 应用。验收：绘制、消息、输入、剪贴板和保存分别通过，不承诺 Office/DirectX/任意游戏。

### 第 4 步

- [ ] **多架构与发行维护**（用户态组件、用户态库、内核机制，前置「Wine 图形与目标应用」、[《原生开发工作站》](./02-workstation.md)的「工具链和开发依赖集合」）：评估新 WoW64 所需执行模式、TLS 和异常，64 位先稳定再扩。验收：每种架构单列结果，保留 Wine LGPL 与修改源码义务，不分发无权分发的 Windows 文件。

## 说明

- Wine 自带 PE 装载器，自研的 PE 实验不是它的前置。
- 复用 Wine 要保留它的代码和 LGPL 许可，发布的修改要有对应源码。不分发无权分发的 Windows 系统文件。

## 通过检查

- [ ] 原生 Wine 下运行同一个受控 PE64 样本，prefix 初始化、进程启动、同步和退出都正常。
- [ ] 图形程序的绘制、消息、输入、剪贴板和保存分别通过。
