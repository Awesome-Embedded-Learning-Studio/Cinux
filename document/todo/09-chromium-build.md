# 09 在 Cinux 里编译 Chromium

浏览器已经能在 Cinux 上运行之后，把构建搬进来，让 Cinux 自己编出自己的浏览器。

进入条件：《独立桌面》的多进程浏览器和《选定发行版的用户态》的大内存、发行版工具链都就绪之后。

## 要达到的行为

- 能做：固定的 Clang、libc++、链接器、GN 和构建执行器在 Cinux 内生成构建图，完成全量、无变化和改源后的增量构建，运行编出来的浏览器。
- 必须失败得对：构建中断和资源不足能报告，不把远程执行的结果算成本地编译。
- 不能据此宣称：复用 GCC 自编译的成绩就等于 Chromium 的工具链已经就位。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **本机构建工具链预演**（用户态组件、用户态库，前置[《独立桌面》](./04-desktop.md)的「多进程与崩溃恢复」、[《原生开发工作站》](./02-workstation.md)的「工具链和开发依赖集合」、[《选定发行版的用户态》](./06-distribution.md)的「大内存与容量配置」、[《多用户服务系统》](./03-services.md)的「多 GiB 文件与长期开发卷」）：将固定 Clang/libc++、链接器、GN 和实际构建执行器搬入 Cinux。验收：生成构建图、编译小目标和代表性链接，预留足够内存/磁盘，不只复用 GCC 自编译成绩。

### 第 2 步

- [ ] **在 Cinux 内全量与增量构建**（用户态组件、测试与证据，前置「本机构建工具链预演」、[《独立桌面》](./04-desktop.md)的「公网与日常功能」）：固定 Chromium 源码修订、配置和依赖，执行最终链接并运行产物。验收：全量/无变化/改源重编均有证据，远程执行不能计为本地编译。

## 说明

- 上游的 Linux 构建文档要求 x86-64、至少 8 GB 内存、强烈建议超过 16 GB、至少 100 GB 可用磁盘，官方支持的工具链是 Clang 和 libc++。本仓库给较完整的构建预留 32 GiB 内存和至少 200 GiB 空间，这是预留量，要靠《选定发行版的用户态》的大内存和《多用户服务系统》的大卷来兑现。

## 通过检查

- [ ] 全量构建、无变化重建和改源重编各有日志，最终链接在本机完成。
- [ ] 编出来的浏览器通过《独立桌面》的那组检查。
