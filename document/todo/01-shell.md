# 01 第 1 级：可信命令行

这一级做完，命令行能当工具用。管道、重定向、文件工具、前后台作业和基本权限都要像参考 Linux 一样工作，失败时返回的错误码也要对得上。

进入条件：没有前置。从[《基线》](./00-baseline.md)的实测结果出发，先把对照测试立起来。

## 这一级要达到的行为

- 能做：管道、追加重定向和 `2>&1`，文件与目录操作，后台任务和 `wait`，Ctrl-C、Ctrl-Z、`bg`、`fg`，两个用户之间的权限约束。
- 必须失败得对：关闭的描述符读返回 EBADF，坏指针返回 EFAULT 且不改偏移，符号链接环返回 ELOOP，普通用户访问无权限的目录和文件被拒绝，非法的 open 标志和 wait 选项按参考行为失败。
- 不能据此宣称：整个 Bash 或 POSIX 已经兼容。POSIX 认证不是这里的目标。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **固定兼容参考集合**（Linux 接口、测试与证据，前置[《基线》](./00-baseline.md)的「冻结并重验起点」）：冻结参考 Linux、glibc、发行版包、LTP/Open POSIX 修订与目标行为。验收：同一个小 ELF 在两边执行，返回值/errno/字段可以比较，范围外行为单列。
- [ ] **修复原生测试脚本的入口**（测试与证据，前置[《基线》](./00-baseline.md)的「冻结并重验起点」）：`test/guest.py` 补上 `import re, os`，让 `test_native_build.py`、`test_native_gui.py`、`test_persistence.py`、`test_gui_tab.py` 能启动。`test/native-build-proof.py` 的横幅定位从 `kernel/kernel.cpp` 改到 `kernel/arch/x86_64/arch_init.cpp`。验收：四个脚本原样运行不再有 `NameError`，`run-cell.sh native` 能走到各自的断言。

### 第 2 步

- [ ] **明确 ABI 与公共模块边界**（内核机制、Linux 接口，前置「固定兼容参考集合」）：梳理参数复制、校验、错误翻译和调用模块，复用现有架构布局。验收：坏指针/未知 flags/未实现调用不越界、不空成功，不要求为了分层搬动全部代码。
- [ ] **可独立运行的行为测试**（测试与证据，前置「固定兼容参考集合」）：先收录文件、clone/wait、mmap、futex 等小程序，支持单项运行和超时。验收：能区分通过、失败、未实现、环境缺失、范围外，不把 skip 计入通过。

### 第 3 步

- [ ] **资源上限的失败行为约定**（内核机制，前置「明确 ABI 与公共模块边界」）：逐类定义页、FD、任务、队列、挂载、网络缓冲耗尽的返回与回收。验收：至少各有一个定向耗尽探针，普通负载不能触发内核停机。
- [ ] **路径解析约定**（内核机制、Linux 接口，前置「明确 ABI 与公共模块边界」）：贯通内部长路径、逐级解析、尾斜线、相对路径与符号链接环。验收：深路径可用，过长返回 ENAMETOOLONG，环返回 ELOOP，失败不越过授权边界。
- [ ] **完整文件元数据**（内核机制、Linux 接口，前置「明确 ABI 与公共模块边界」）：在公共结构和后端中保留 uid/gid/mode/nlink/size/时间，stat/statx 正确交付，补 utimensat/futimens。验收：不同属主、硬链接数和文件类型如实返回，不用固定零冒充真实字段。基线实测调用号 280 未实现让客体里 CMake configure 失败，修好后 `cmake -B build -S .` 能走完。
- [ ] **描述符与打开文件对象分离**（内核机制、Linux 接口，前置「明确 ABI 与公共模块边界」）：验证 dup、fork 共享偏移、描述符独立 CLOEXEC 和文件状态 flags。验收：关闭一个别名不提前释放对象，坏 FD 为 EBADF，exec 只关闭应关闭的 FD。
- [ ] **ABI 行为清单逐组升级**（Linux 接口、测试与证据，前置「可独立运行的行为测试」）：从文件/进程/内存扩到 IPC/网络/ioctl/proc/sys，保留差异台账。验收：每组有固定正反测试，ENOSYS 回退与确实必需的调用分开，不按总数报兼容率。

### 第 4 步

- [ ] **故障注入与清理计数**（内核机制、测试与证据，前置「资源上限的失败行为约定」、「可独立运行的行为测试」）：给分配、I/O、复制用户数据加入测试用失败点。验收：失败后页/FD/队列引用恢复，重复触发不累积泄漏。
- [ ] **定位 I/O 与截断**（内核机制、Linux 接口，前置「完整文件元数据」、「描述符与打开文件对象分离」）：补齐 pread/pwrite、truncate/ftruncate、readv/writev 的范围和短传输语义。验收：定位写不改共享偏移，扩展空洞读取为零，负偏移/溢出被拒绝。
- [ ] **链接与目录重命名**（内核机制、Linux 接口，前置「路径解析约定」、「完整文件元数据」）：支持所选后端的硬/软链接和目录 rename，维护父子关系。验收：移动目录后路径和链接数正确，禁止目录循环和非法类型替换。

### 第 5 步

- [ ] **生命周期与退出取消**（内核机制、Linux 接口，前置「故障注入与清理计数」）：统一任务终止与各类等待队列的脱离规则。验收：线程阻塞在 futex/pipe/wait 时，另一线程 exit_group 或外部 SIGKILL 后可限时回收，无悬挂队列项。
- [ ] **打开后删除的寿命**（内核机制，前置「描述符与打开文件对象分离」、「链接与目录重命名」）：区分路径消失、inode 引用和磁盘回收。验收：unlink 后旧 FD 可读写，最后引用关闭才释放，重启后不泄漏已删除文件。

### 第 6 步

- [ ] **信号状态归属**（内核机制、Linux 接口，前置「生命周期与退出取消」）：共享处置表，分离线程掩码/线程待决和进程待决。验收：线程 A 屏蔽信号不改变 B，tgkill 定向到 B，fork 继承掩码但不继承 pending。
- [ ] **exec 与线程边界**（内核机制、Linux 接口，前置「生命周期与退出取消」、「描述符与打开文件对象分离」）：验证多线程 exec、CLOEXEC、TLS/栈、shebang 与失败回滚。验收：成功 exec 后只保留正确执行上下文，失败不丢调用进程原有资源。
- [ ] **凭据和元数据贯通**（内核机制、Linux 接口，前置「完整文件元数据」、「生命周期与退出取消」）：明确 real/effective/saved IDs、补充组、凭据复制/共享规则。验收：创建文件与 stat 对应调用者，fork/exec/线程的身份变化与参考行为一致。

### 第 7 步

- [ ] **标准信号帧与备用栈**（内核机制、Linux 接口，前置「信号状态归属」）：交付 siginfo/ucontext、sigaltstack 与恢复规则。验收：备用栈收到故障地址和寄存器，处理返回后恢复上下文，不允许越权修改用户不可控制的状态。
- [ ] **可中断阻塞与重启**（内核机制、Linux 接口，前置「信号状态归属」）：逐项定义 read/connect/poll/futex/wait 的 EINTR、SA_RESTART 与剩余超时。验收：信号不会丢唤醒、吞掉已传输字节或无限延长固定期限。
- [ ] **公共路径访问检查**（内核机制、Linux 接口，前置「凭据和元数据贯通」、「路径解析约定」）：逐级检查目录搜索、文件读写执行和 access 与 open 的身份差异。验收：两个 UID 的 owner/group/other 与无目录 x 场景均按预期允许或拒绝。
- [ ] **进程和管理操作鉴权**（内核机制、Linux 接口，前置「凭据和元数据贯通」）：统一 kill/tkill/tgkill、身份切换、mount、校时和资源管理的授权，按支持范围实现 capability。验收：跨 UID signal 0 也受限，放弃的权限不能自行恢复，未实现特权不能空成功。

### 第 8 步

- [ ] **停止/继续与终端作业**（内核机制、Linux 接口，前置「生命周期与退出取消」、「可中断阻塞与重启」）：补 wait 的 stop/continue 事件与终端前台进程组行为。验收：Ctrl-Z→bg→fg、Ctrl-C 只影响前台任务，子状态只报告/回收相应次数。
- [ ] **rt_sigsuspend 与 shell 的 wait**（内核机制、Linux 接口，前置「信号状态归属」、「可中断阻塞与重启」）：x86_64 调用号 130 未实现，BusyBox ash 的 `wait` 因此空转并刷屏。验收：`sleep 1 & wait` 返回且没有 unserved 打印，信号到达时掩码按规则切换和恢复。
- [ ] **目录 FD 与 *at 操作**（内核机制、Linux 接口，前置「路径解析约定」、「描述符与打开文件对象分离」、「公共路径访问检查」）：统一 openat/fstatat/renameat/unlinkat 等目录基准和符号链接 flags。验收：并发改 cwd 不改变目录 FD 定位，非法 flags 和越权访问正确失败。
- [ ] **创建、umask 和改属性**（内核机制、Linux 接口，前置「公共路径访问检查」）：对创建、chmod/chown/链接删除使用同一授权模型。验收：umask 真影响新文件，普通用户不能改别人文件权限，失败不部分更改元数据。
- [ ] **统一等待与取消约定**（内核机制，前置「可中断阻塞与重启」）：明确条件检查、入队、唤醒、关闭、超时和退出竞争。验收：重复竞争无丢唤醒，取消后队列无死任务，唤醒不解引用已关闭对象。

### 第 9 步

- [ ] **特殊权限位**（内核机制、Linux 接口，前置「创建、umask 和改属性」、「exec 与线程边界」）：逐项实现 sticky、setgid 目录和受控 setuid/setgid exec，禁止意外提权。验收：共享目录互删被拒绝，特权位在写入/执行中的清理和凭据变化有对照测试。
- [ ] **poll/select 的原子等待**（内核机制、Linux 接口，前置「统一等待与取消约定」、「信号状态归属」）：补目标范围的 select/pselect/ppoll 和信号掩码切换。验收：就绪/关闭/信号同到达不永久挂起，大 FD 集合合法拒绝或正常处理。
- [ ] **管道、FIFO 与挂断**（内核机制、Linux 接口，前置「统一等待与取消约定」、「链接与目录重命名」、「可中断阻塞与重启」）：复核 PIPE_BUF 原子性、非阻塞、FIFO 打开和读者消失。验收：`echo pipe | cat` 保持通过，基线实测挂起的 `yes | head -1` 能正常结束，EPIPE/SIGPIPE 正确，关闭/信号/部分传输竞争不挂死，挂起时 Ctrl-C 能回到 shell。

## 说明

- 基线实测留下两个挂起点：`yes | head -1` 读者退出后写端不结束，`sleep 1 & wait` 因为 `rt_sigsuspend` 未实现而空转。两项都在这一级解决。
- 「ABI 行为清单逐组升级」是一条一直做下去的差异台账。每一级的新探针都并进去，通过、失败、未实现、环境不具备、范围外分开记，不按系统调用总数报兼容率。

## 通过这一级的检查

- [ ] 管道：`yes | head -1` 输出一行 y 后正常结束，`echo pipe | cat` 输出 pipe。
- [ ] 作业控制：后台任务能 `wait` 到，Ctrl-C 只中断前台作业，Ctrl-Z 之后 `bg`、`fg` 能来回切，退出后没有僵尸进程和错误的终端状态。
- [ ] 文件：目录重命名后子路径正确，进程打开文件后删除路径仍可读，最后引用关闭才释放。
- [ ] 权限：两个 UID 下 owner、group、other 和目录搜索位的行为与参考 Linux 一致，`chmod`、`kill`、`signal 0` 对无权对象返回 EPERM。
- [ ] 参考 Linux 和 Cinux 各跑一遍同一组探针，比较返回值、errno、状态变化和资源回收。PID、地址、时钟这类不确定的值先规范化再比。
