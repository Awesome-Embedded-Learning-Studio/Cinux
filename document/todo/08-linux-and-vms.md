# 08 编译 Linux，运行虚拟机

在 Cinux 里编出一个能启动的 Linux 内核，再让 Cinux 自己运行 QEMU，用软件模拟启动它，最后启动 Ubuntu 和桌面。

进入条件：构建工具和可靠工作卷在《原生开发工作站》就绪后可以开始。QEMU 的运行时探针只要求那一份里的线程、信号、内存和定位 I/O，不用等 Linux 编完。

## 要达到的行为

- 能做：固定版本和配置的 Linux 内核在 Cinux 内编出来并启动。原生 QEMU 用单线程 TCG、串口和最少设备执行客体代码，再挂 raw 磁盘启动 Ubuntu，接网络、桌面和浏览器。
- 必须失败得对：构建被中断后没有遗留的子进程，满盘和内存不足能报告，客体退出不需要重启外层 Cinux，关机后磁盘内容一致。
- 不能据此宣称：Cinux 内核变成了 Linux。虚拟机里的程序由客体自己的 Linux 内核管理，不计入 Cinux 的原生兼容成绩。软件模拟下能启动，不等于适合每天上网。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **准备构建工具包**（用户态组件，前置[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」、[《可信命令行》](./01-shell.md)的「可中断阻塞与重启」、[《原生开发工作站》](./02-workstation.md)的「跨越现有单文件限制」）：固定 Bash、Perl、GNU Make、GCC/binutils、Flex/Bison、bc 和配置相关库，早期可用受控离线 overlay，不等包管理产品。验收：逐个执行实际生成/编译任务，不以版本输出代替可用。
- [ ] **GLib 和运行时探针**（用户态组件、用户态库，前置[《可信命令行》](./01-shell.md)的「可独立运行的行为测试」、[《可信命令行》](./01-shell.md)的「生命周期与退出取消」、[《原生开发工作站》](./02-workstation.md)的「VMA 与映射生命周期」、[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」）：在现有能力上分别测线程、JIT、计时、事件与定位 I/O，固定版本。验收：产出必需和可回退的依赖清单。缺的内核能力在《可信命令行》和《原生开发工作站》里对应的事件通知、共享对象和信号帧任务里补齐，再更新「最小 QEMU 装载」的前置。有探针结果不等于运行时已通过。

### 第 2 步

- [ ] **Kconfig 和主机工具**（用户态组件、Linux 接口，前置「准备构建工具包」）：从干净输出目录生成配置和 host tools。验收：ARCH/HOSTCC 等显式配置正确，不伪造全局 uname 来绕过平台检测。
- [ ] **最小 QEMU 装载**（用户态组件，前置「GLib 和运行时探针」）：必须先完成「GLib 和运行时探针」识别并登记的硬依赖。可先在 Linux 构建，再拿到 Cinux 原生执行，构建时只带 x86 system/TCG 所需组件。验收：版本/配置及初始化正确，这是烟测，不是模拟器完成。

### 第 3 步

- [ ] **最小可启动配置**（用户态组件，前置「Kconfig 和主机工具」）：保留串口、ELF、initramfs 和最小用户态，按版本处理 BTF/签名/Rust 等依赖。验收：配置可重复生成，裁剪不删除目标启动所需能力。
- [ ] **TCG 执行测试客体**（用户态组件，前置「最小 QEMU 装载」）：使用单虚拟 CPU、单线程 TCG、串口和最少设备。验收：真正执行客体指令输出标记并退出，外层 Cinux 可继续交互。QEMU 辅助线程仍需正确运行。

### 第 4 步

- [ ] **串行与有限并行全量构建**（用户态组件、测试与证据，前置「最小可启动配置」、[《原生开发工作站》](./02-workstation.md)的「OOM 与保留资源」）：先单作业，再逐步增加并行。验收：得到内核及符号产物，Ctrl-C 后无遗留构建子进程，满盘/内存不足能报告。
- [ ] **最小 Linux 客体**（用户态组件，前置「TCG 执行测试客体」）：通过直接内核/initramfs 启动已知 Linux+BusyBox，不先接盘/网/显示。验收：进入 shell，内层 uname 为 Linux，客体退出不需要重启 Cinux。

### 第 5 步

- [ ] **产物启动与增量构建**（用户态组件、测试与证据，前置「串行与有限并行全量构建」）：先用外部参考 QEMU 验证产物，再测无变化/改源增量。验收：确实启动到用户态，保存哈希与日志。这不算 Cinux 内 QEMU 已完成。
- [ ] **raw 磁盘与 Ubuntu 串口**（用户态组件，前置「最小 Linux 客体」、[《多用户服务系统》](./03-services.md)的「多 GiB 文件与长期开发卷」、[《原生开发工作站》](./02-workstation.md)的「文件/目录同步约定」）：固定 Ubuntu cloud image，可预转换 raw、生成 NoCloud seed，匹配固件或 direct boot。验收：登录、写文件、正常关机和重启保留数据，不把 .img 扩展名当格式判断。

### 第 6 步

- [ ] **使用 Cinux 自编 Linux**（用户态组件、测试与证据，前置「最小 Linux 客体」、「产物启动与增量构建」）：替换已知内核完成组合验收。验收：重复运行、启动、退出和资源回收成立，形成 Cinux → QEMU → 自编 Linux 的完整证据。
- [ ] **Ubuntu 网络与软件**（用户态组件，前置「raw 磁盘与 Ubuntu 串口」、[《多用户服务系统》](./03-services.md)的「HTTPS 与远程访问」）：接用户态网络和目标软件包安装。验收：DNS/HTTPS/SSH、下载和包安装可用，客体 Linux 负责其 ext4/systemd，不计入 Cinux 原生能力。

### 第 7 步

- [ ] **Ubuntu 桌面与浏览器**（用户态组件，前置「Ubuntu 网络与软件」、[《独立桌面》](./04-desktop.md)的「原生 VNC 查看器」）：可先外部 VNC 查看，再接 Cinux 查看器，验证预构建浏览器。验收：实际键鼠浏览与下载，记录延迟/CPU/RAM。TCG 启动成功不等于日常流畅。

## 说明

- TCG 是把客体指令翻译成本机代码的软件模拟，不依赖 Cinux 的硬件虚拟化。硬件加速在《硬件虚拟化》里单独做。
- 客体的 ext4、systemd 和浏览器由客体 Linux 负责，外层只需要可靠地保存足够大的镜像文件。
- Ubuntu 云镜像可能是 QCow2 加 UEFI/GPT，不能按扩展名当成 raw。固件或者直接内核启动的方式要先定下来。

## 通过检查

- [ ] Cinux 内编出的内核先在外部的参考 QEMU 启动到用户态，再由 Cinux 里的 QEMU 启动，重复运行不需要重启 Cinux。
- [ ] Ubuntu 经串口登录，写盘、同步关机、重启后数据保留。
- [ ] DNS、HTTPS、SSH 和固定的软件包安装可用，浏览器能操作并保存下载，延迟、CPU 和内存有记录。
