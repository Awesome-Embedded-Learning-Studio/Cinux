# 07 Windows 里好用的功能

把事件等待、整棵进程树的管理、完成式异步 I/O，以及服务、安装和桌面上的顺手体验做成 Cinux 自己的能力。这些功能服务 Cinux 自己的程序，不绑定 PE、Windows DLL 或者 NT 内核。

进入条件：事件等待在《可信命令行》的「统一等待与取消约定」和《原生开发工作站》的 futex、eventfd 之后可以开始。进程树的限额要等《多用户服务系统》的资源组控制器，完成队列的后半段要等它的块设备和网络行为，应用进程树和桌面上的体验要等《独立桌面》。

## 要达到的行为

- 能做：手动和自动复位事件，wait-any 和 wait-all，不可逃离的应用进程树，带请求编号和终态的完成队列，服务控制和安装恢复的入口。
- 必须失败得对：未全就绪时不提前消费事件，普通应用不能加入或者结束别人的进程树，取消和完成竞争不重复释放，队列满时明确拒绝。
- 不能据此宣称：epoll 的就绪通知等于 I/O 完成结果，线程池原型等于内核异步 I/O，自有服务控制等于兼容 Windows 的 SCM，自有安装器支持 MSI。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **手动复位事件**（用户态库、内核机制，前置[《可信命令行》](./01-shell.md)的「统一等待与取消约定」、[《原生开发工作站》](./02-workstation.md)的「futex 身份与共享等待」）：先交付 set/reset 与进程内等待，复用公共等待机制。验收：先 set 后 wait 不丢信号，多等待者均可观察已置位，reset/关闭/超时竞争可解释。
- [ ] **应用树与关闭策略**（用户态库、用户态组件，前置[《多用户服务系统》](./03-services.md)的「应用/服务资源组」、[《独立桌面》](./04-desktop.md)的「稳定进程引用与回收」）：对公共资源组提供 create/attach/query、统一结束和 kill-on-close。验收：父退出、子 setsid 后仍可整体管理，关闭/成员退出竞争不误杀别人。
- [ ] **有界请求与完成协议**（用户态库、用户态组件，前置[《原生开发工作站》](./02-workstation.md)的「epoll 的完整目标语义」、[《原生开发工作站》](./02-workstation.md)的「时钟与 timerfd」、[《原生开发工作站》](./02-workstation.md)的「SCM_RIGHTS 描述符传递」）：定义请求 ID、缓冲寿命、队列上限和唯一终态，用有界线程池作原型后端。验收：队列满可拒绝，错误/短传输不丢，不宣称驱动异步 I/O 已有。
- [ ] **安装卸载与恢复体验**（用户态组件，前置[《原生开发工作站》](./02-workstation.md)的「软件包与文件归属」、[《多用户服务系统》](./03-services.md)的「升级事务和回滚」、[《独立桌面》](./04-desktop.md)的「剪贴板、拖放和文件选择」）：用公共软件管理后端做安装器和恢复入口。验收：可取消、升级失败恢复旧版、卸载保护共享文件，不默认支持 MSI。
- [ ] **桌面易用功能**（用户态组件，前置[《独立桌面》](./04-desktop.md)的「Vesper 与标准平台连接」、[《独立桌面》](./04-desktop.md)的「字体与中文输入」、[《独立桌面》](./04-desktop.md)的「剪贴板、拖放和文件选择」）：逐项实现窗口吸附、快捷键、统一打开/保存、拖放和应用关联。验收：多进程应用实际使用，不把文件关联/注册表式设置机制放进内核。

### 第 2 步

- [ ] **自动复位与 wait-any**（用户态库、内核机制，前置「手动复位事件」、[《原生开发工作站》](./02-workstation.md)的「eventfd 计数与关闭」）：增加一次性消费和多对象任选等待。验收：一个信号只由一个成功等待消费，未选中的对象状态不被误改，关闭无丢唤醒。
- [ ] **Job 风格资源接口**（用户态库、用户态组件，前置「应用树与关闭策略」、[《多用户服务系统》](./03-services.md)的「资源组任务数控制」、[《多用户服务系统》](./03-services.md)的「资源组内存控制」、[《多用户服务系统》](./03-services.md)的「资源组 CPU 控制」）：包装同一内核控制器，分别接进程数/内存/CPU 限额与查询。验收：真实执行、不越权、不维护第二套统计，Windows 风格库不是任务管理器的硬前置。
- [ ] **完成式文件复制**（用户态库、用户态组件，前置「有界请求与完成协议」、[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」）：先完成普通文件读写请求和结果投递。验收：多文件复制内容正确，每个接受请求恰有一个终态，短读/短写/磁盘错误可区分。
- [ ] **服务控制体验**（用户态组件，前置[《原生开发工作站》](./02-workstation.md)的「服务生命周期最小版本」、[《多用户服务系统》](./03-services.md)的「日志服务」、「应用树与关闭策略」）：增加服务状态、依赖、启动类型和图形/命令行控制。验收：停止整个服务应用、退避重启、日志查询可用，不在内核实现 SCM RPC 或服务配置数据库。

### 第 3 步

- [ ] **跨进程事件与名字服务**（用户态库、用户态组件，前置「自动复位与 wait-any」、[《原生开发工作站》](./02-workstation.md)的「匿名共享映射」、[《原生开发工作站》](./02-workstation.md)的「UNIX 套接字身份与名字」）：先通过 FD/共享对象传递，再增加受权名字与寿命策略。验收：非授权进程不能冒名接管，创建者退出不破坏仍有引用的对象。
- [ ] **取消与退出回收**（用户态库、用户态组件、内核机制，前置「完成式文件复制」、[《可信命令行》](./01-shell.md)的「生命周期与退出取消」）：明确超时、取消失败、关闭与完成竞争。验收：终态前缓冲仍有效，不重复释放，发起进程退出后任务可收尾。取消请求不等于 I/O 已停止。

### 第 4 步

- [ ] **wait-all 原子消费**（用户态库、用户态组件、内核机制，前置「跨进程事件与名字服务」）：定义多对象原子状态消费，可由库/对象服务组织，必要时增加通用原语。验收：未全就绪不提前消费事件，不能靠逐个等待冒充同等语义。
- [ ] **完成式套接字请求**（用户态库、用户态组件，前置「取消与退出回收」、[《多用户服务系统》](./03-services.md)的「套接字通用行为」）：接 accept/连接/收发和对端关闭。验收：多客户端服务正确传输，断连和部分收发有终态，不把 epoll 就绪通知直接算完成。

### 第 5 步

- [ ] **内核异步请求生命周期**（内核机制，前置「完成式套接字请求」、[《原生开发工作站》](./02-workstation.md)的「块 I/O 故障与持久化顺序」、[《多用户服务系统》](./03-services.md)的「TCP 容量与压力恢复」）：逐步把提交/完成/取消接入公共块与网络路径。验收：在完成前保持缓冲与对象有效，取消不代表物理 I/O 一定没发生，退出可安全收尾。

### 第 6 步

- [ ] **完成端口与工作线程策略**（用户态库、用户态组件、内核机制，前置「内核异步请求生命周期」）：将完成通知后端接回库，增加有界并发与批量消费。验收：并行复制/多客户端服务实际完成数据传输，不把 epoll 可读写通知说成请求完成。

## 说明

- 进程内的事件先由库用 futex 实现。跨进程的事件基于共享内存和可等待的描述符，对象的名字和清理由受控的用户态服务管。
- Job 与 cgroup 共用同一套内核控制器，不维护第二套统计。任务管理器直接用公共资源组，不依赖这里的包装库。

## 通过检查

- [ ] set 发生在 wait 之前、竞争等待、超时和 set 同时发生，都没有丢唤醒。
- [ ] 父、子、孙进程在 setsid 和重新认父之后仍能被整体结束，限额真实执行。
- [ ] 并行文件复制和多客户端服务里，每个已接受的请求恰好有一个终态。
