# 06 第 6 级：选定发行版的用户态

这一级做完，一组明确版本的 Linux 软件能在 Cinux 上长期使用：包能装能升级，服务、桌面和容器开机自启，出故障能恢复。

进入条件：[《容器运行环境》](./05-containers.md)的检查全部通过。

## 这一级要达到的行为

- 能做：真实包管理器的安装、升级、卸载和维护脚本，固定的 systemd、D-Bus、设备和网络服务，桌面会话和 OCI 工具，VirtualIO 设备和更多启动路径。
- 必须失败得对：中断升级、坏包、坏签名、依赖冲突、配置冲突、磁盘满、服务升级失败、降权后的维护脚本、受限设备访问都要报告并恢复，不能靠隐藏失败、忽略脚本返回值或改软件源码换通过。
- 不能据此宣称：所有 Linux 软件、所有内核模块、所有设备驱动和文件系统、任意版本的发行版都可用。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **大内存与容量配置**（内核机制，前置[《原生开发工作站》](./02-workstation.md)的「OOM 与保留资源」、[《原生开发工作站》](./02-workstation.md)的「公平调度与 CPU 归属」）：分离容量参数和策略，验证超过 16 GiB 的物理地址及页管理数据结构。验收：高地址页确实分配/读写/回收，不能只增加启动参数。4–8 GiB 的常用配置继续回归。
- [ ] **VirtIO 块设备**（内核机制，前置[《多用户服务系统》](./03-services.md)的「设备模型接口封口」、[《原生开发工作站》](./02-workstation.md)的「块 I/O 故障与持久化顺序」）：按块接口增加后端。验收：同一 VFS/文件测试在 AHCI/NVMe 与 VirtIO 后端运行，队列错误和刷新不丢失。
- [ ] **VirtIO 网络设备**（内核机制，前置[《多用户服务系统》](./03-services.md)的「设备模型接口封口」、[《多用户服务系统》](./03-services.md)的「接口、地址和路由配置」）：按网络设备接口接入，不复制 TCP 栈。验收：同组网络行为在 e1000/VirtIO 切换后成立，驱动失败不损坏协议状态。
- [ ] **热插拔与事件**（内核机制、用户态组件，前置[《多用户服务系统》](./03-services.md)的「设备模型接口封口」、[《多用户服务系统》](./03-services.md)的「设备策略服务」）：先实现一个受控添加/删除路径与重新枚举。验收：打开设备时移除按约定失败，旧句柄不指向新设备，服务能恢复状态。
- [ ] **UEFI 启动入口**（内核机制，前置[《多用户服务系统》](./03-services.md)的「设备模型接口封口」、[《多用户服务系统》](./03-services.md)的「MBR/GPT 分区与块节点」）：新增固件内存图、帧缓冲和启动参数交付，复用后面的公共初始化。验收：同一系统在选定 BIOS/UEFI 环境分别启动，不把它设为早期 shell、服务或 QEMU 串口的门槛。
- [ ] **真实 dpkg/apt 路径**（用户态组件、Linux 接口，前置[《原生开发工作站》](./02-workstation.md)的「软件包与文件归属」、[《多用户服务系统》](./03-services.md)的「信任库与安全更新」、[《原生开发工作站》](./02-workstation.md)的「动态链接与系统数据库」、[《多用户服务系统》](./03-services.md)的「文件变化通知」）：安装受控包集合并运行维护脚本，继续验证升级/卸载。验收：依赖冲突、坏签名、失败脚本和满盘可报告并恢复，不能忽略脚本返回值换通过。

### 第 2 步

- [ ] **USB 大容量存储**（内核机制、用户态组件，前置「热插拔与事件」、[《多用户服务系统》](./03-services.md)的「FAT32 交换卷」）：在已有 USB 控制器基础上增加所选存储传输，接公共块层。验收：插入读写 FAT32 卷、拔出报错与重新插入不混用旧引用。
- [ ] **电源管理扩展**（内核机制、用户态组件，前置[《多用户服务系统》](./03-services.md)的「固件与电源基本路径」、「热插拔与事件」）：按目标硬件逐步增加空闲、频率、温度/电池与挂起恢复。验收：每个已声明平台单独测试恢复后的时钟、存储和输入，未支持平台明确列出。
- [ ] **systemd/D-Bus/设备服务范围**（用户态组件、Linux 接口，前置[《多用户服务系统》](./03-services.md)的「设备策略服务」、[《容器运行环境》](./05-containers.md)的「cgroup v2 目标接口」、[《独立桌面》](./04-desktop.md)的「权限下降与 seccomp」、[《原生开发工作站》](./02-workstation.md)的「procfs 进程视图」、「热插拔与事件」、[《原生开发工作站》](./02-workstation.md)的「signalfd」、[《多用户服务系统》](./03-services.md)的「文件变化通知」）：固定版本和目标 units，补实际依赖接口。验收：服务就绪/停止/socket 激活/权限/重启策略按清单运行，不能仅启动 PID1 就宣布支持。

### 第 3 步

- [ ] **发行版桌面与容器集合**（用户态组件、Linux 接口，前置[《独立桌面》](./04-desktop.md)的「工具包与会话集成」、[《独立桌面》](./04-desktop.md)的「桌面应用沙箱」、[《容器运行环境》](./05-containers.md)的「容器网络与镜像层」、「真实 dpkg/apt 路径」、「systemd/D-Bus/设备服务范围」）：接固定会话、图形程序与 OCI 工具。验收：登录后启动、注销回收、软件安装和隔离互相不破坏，兼容选项逐项列明。

### 第 4 步

- [ ] **长期行为与恢复门槛**（测试与证据、用户态组件，前置[《原生开发工作站》](./02-workstation.md)的「工具链和开发依赖集合」、「发行版桌面与容器集合」、[《多用户服务系统》](./03-services.md)的「ext4 根盘与维护模式」、[《多用户服务系统》](./03-services.md)的「IPv6 基础网络」、「电源管理扩展」）：按明确硬件范围运行持续构建/服务/桌面/容器和更新恢复。验收：保存吞吐/延迟/内存增长/重启恢复证据，报告未支持范围，而非口头标记“Linux 平替完成”。

## 说明

- “接近替代”指一个版本化的目标集合：固定的发行版、软件包、服务和设备范围。《可信命令行》开头定下的参考环境就是这把尺子。
- 自己的组件可用和上游组件兼容分别记成绩。systemd 自己启动成功不等于它的全部 unit 指令都支持。

## 通过这一级的检查

- [ ] 从干净的根文件系统安装受控包集合，运行维护脚本，升级、卸载和重启都成立。
- [ ] 固定的 systemd 版本和目标 unit 的就绪、停止、socket 激活、权限和重启策略按清单运行。
- [ ] 登录之后桌面会话和容器工具自启动，注销之后回收。
- [ ] 持续构建、服务、桌面、容器和更新恢复各跑一段固定的长跑时间，吞吐、延迟、内存增长和重启恢复都有记录。
- [ ] 未支持的范围写清楚，不用一句“完成”带过。
