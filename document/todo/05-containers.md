# 05 第 5 级：容器运行环境

这一级做完，一个展开的根文件系统能在隔离里运行。进程、挂载、用户、IPC 和网络的视图各自独立，资源限制真实生效。

进入条件：[《独立桌面》](./04-desktop.md)的检查全部通过。

## 这一级要达到的行为

- 能做：固定运行时的最小 OCI 包，加上网络，再加上镜像层和非特权运行。
- 必须失败得对：容器里的 root 拿不到外层 root 的权限，不能向外层进程发信号、修改外层挂载或打开任意设备，进程数和内存越限被限制，实例退出后命名空间、挂载、网络设备和资源组都能回收，错误配置被拒绝。
- 不能据此宣称：chroot 等于容器，一个 OCI 包成功等于完整的 Docker 或 Kubernetes，资源限制文件能读写就等于限制已经生效。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **SysV 共享内存寿命与权限**（内核机制、Linux 接口，前置[《原生开发工作站》](./02-workstation.md)的「匿名共享映射」、[《可信命令行》](./01-shell.md)的「公共路径访问检查」）：复用已有共享页实现，补 ID、IPC_RMID、最后分离和身份检查。验收：标记删除不提前破坏已有映射，ID 复用不误接旧对象，跨用户访问受限。
- [ ] **SysV 信号量**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「统一等待与取消约定」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：按目标范围接原子操作组、等待、退出撤销和控制权限。验收：多操作失败不部分生效，进程退出后的 SEM_UNDO 正确，不因对象删除永久挂起。
- [ ] **SysV 消息队列**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「统一等待与取消约定」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：接消息类型选择、容量、非阻塞和对象删除。验收：队列满可拒绝/等待，删除唤醒等待者，长度与用户指针失败不泄漏消息。
- [ ] **cgroup v2 目标接口**（内核机制、Linux 接口，前置[《多用户服务系统》](./03-services.md)的「单进程限额执行」、[《多用户服务系统》](./03-services.md)的「资源组任务数控制」、[《多用户服务系统》](./03-services.md)的「资源组内存控制」、[《多用户服务系统》](./03-services.md)的「资源组 CPU 控制」、[《原生开发工作站》](./02-workstation.md)的「通用挂载生命周期」）：按范围实现层级、成员、控制器、统计与委派，未支持控制器不伪装存在。验收：子组不能扩大父组限制，无权迁移拒绝，退出可回收。
- [ ] **用户命名空间**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」、[《独立桌面》](./04-desktop.md)的「挂载命名空间」）：定义 UID/GID 映射、映射写入授权和 namespace 内特权。验收：内部 root 不是外部 root，设备/文件/管理调用都使用正确身份。

### 第 2 步

- [ ] **IPC 与 UTS 隔离**（内核机制、Linux 接口，前置「用户命名空间」、「SysV 共享内存寿命与权限」、「SysV 信号量」、「SysV 消息队列」）：先分别交付主机名视图和所支持 SysV/POSIX IPC 对象隔离。验收：两个实例的名字/对象独立，退出可回收，不只是隐藏显示结果。不把 AF_UNIX 的隔离错误地全归到 IPC namespace。
- [ ] **网络命名空间**（内核机制、Linux 接口，前置「用户命名空间」、[《多用户服务系统》](./03-services.md)的「Linux 网络管理接口」）：隔离接口、路由、地址、端口与网络策略，明确 AF_UNIX 抽象名字等对象归属。验收：两实例可绑定同端口，内外查询与数据路径一致，销毁后无残留设备/路由。
- [ ] **最小 OCI bundle**（用户态组件、用户态库，前置「cgroup v2 目标接口」、[《独立桌面》](./04-desktop.md)的「PID 命名空间」、[《独立桌面》](./04-desktop.md)的「权限下降与 seccomp」、[《独立桌面》](./04-desktop.md)的「根目录、bind 与只读挂载」）：固定 runtime 与 rootful profile，先展开 rootfs、受控设备，清理继承网络 FD 并用 seccomp 禁止网络创建/访问。验收：shell 启动、限额和网络拒绝真实生效，退出均清理。不宣称 userns/rootless 或完整隔离已通过，也不把未设置 netns 的默认继承叫无网络。

### 第 3 步

- [ ] **容器网络与镜像层**（用户态组件、内核机制，前置「最小 OCI bundle」、「IPC 与 UTS 隔离」、「网络命名空间」、[《多用户服务系统》](./03-services.md)的「写回与异常停机恢复」）：先加网络，再按需要增加 overlay 或其他层存储后端和镜像工具。验收：实例读写层互不污染，断网/层损坏有错误，不能把镜像解包成功当运行成功。

### 第 4 步

- [ ] **rootless 与完整工具体验**（用户态组件、内核机制，前置「容器网络与镜像层」、「用户命名空间」、[《多用户服务系统》](./03-services.md)的「信任库与安全更新」）：补委派、非特权映射及固定 Podman/Docker 路径。验收：普通用户创建的实例不能逃逸或提升限额，文档明确支持的运行选项和未支持项。

## 说明

- 最小 OCI 从已展开的 rootfs、受控设备和网络拒绝开始，不等 OverlayFS、镜像仓库和 Docker daemon。
- rootful、网络和层存储、rootless 三档分别公布结果，不能用其中一档通过代表全部通过。用户命名空间和对应的安全测试完成之前，不把 rootless 标为支持。
- 服务资源组、Windows 风格的 Job 和 Linux 的 cgroup 共用同一套归属和限额执行点。

## 通过这一级的检查

- [ ] 最小 OCI 包启动 shell，限额生效，网络创建和访问被拒绝，正常和异常退出都清理干净。
- [ ] 挂载、PID、用户、IPC、UTS、网络命名空间各自独立，内外 PID 查询一致可解释，容器 root 不是外层 root。
- [ ] seccomp 禁止的调用确实被拒绝或终止，过滤跨线程和 exec 的继承正确。
- [ ] 加入网络和镜像层之后，两个实例的读写层互不污染。
- [ ] 非特权用户创建的实例不能逃逸，也不能提升限额。
