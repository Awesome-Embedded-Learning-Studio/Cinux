# 02 第 2 级：原生开发工作站

这一级做完，Cinux 能当开发机用。固定的 Git、Python、SQLite、Make、CMake、Ninja 能在它上面稳定工作，有限并行构建能跑完，出了问题有办法定位。

进入条件：[《可信命令行》](./01-shell.md)的检查全部通过。

## 这一级要达到的行为

- 能做：共享和私有映射，线程信号，超时取消，文件锁，增量构建，在低内存下失败而不拖垮系统，用 strace、core 和 GDB 的选定路径定位崩溃。
- 必须失败得对：MAP_PRIVATE 不回写原文件，写只读页得到 SIGSEGV，截断后的映射访问有明确边界，EMFILE、ENOSPC、ENOMEM 按参考行为返回，构建中 Ctrl-C 之后没有遗留的子进程和描述符。
- 不能据此宣称：编出 Linux 内核就等于广泛的 Linux 用户态兼容，或者跑通一套 glibc 就等于别的 libc 和架构都支持。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **公平调度与 CPU 归属**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「生命周期与退出取消」）：验证抢占、可运行队列、CPU affinity 与迁移，扩展已有调度策略接口。验收：忙循环不饿死 shell，跨核并发唤醒不丢任务，离线/非法 CPU 掩码被拒绝。
- [ ] **标准线程创建路径**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「可独立运行的行为测试」、[《可信命令行》](./01-shell.md)的「生命周期与退出取消」）：基线实测开发卷里 glibc 2.44 的 `pthread_create` 返回 EINVAL，且没有打印 unserved 调用，要逐个标志找出被拒绝的组合。验收：4 线程 create/join 探针通过，`strace` 路径能对照参考 Linux 的 clone 参数，线程数上限按 rlimit 拒绝。
- [ ] **文件锁**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」、[《可信命令行》](./01-shell.md)的「可中断阻塞与重启」）：分别验证 flock 与 fcntl 记录锁的归属、冲突、继承和关闭规则。验收：两进程冲突锁可等待/中断，退出释放，不把不同锁模型当同一个互斥量。
- [ ] **通用挂载生命周期**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「路径解析约定」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：在后端注册和引用管理上扩 mount/umount、只读和 busy 检查。验收：能挂载持久卷，持有文件时按规则拒绝或延迟卸载，不能释放仍在使用的后端。
- [ ] **登录认证与降权**（用户态组件、用户态库，前置[《可信命令行》](./01-shell.md)的「创建、umask 和改属性」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：账户解析/密码或密钥认证在用户态，内核执行组和身份切换。验收：非 root 登录后的子进程均正确降权，坏凭据不进入会话，秘密文件有真实保护。
- [ ] **缺页和 COW 失败安全**（内核机制，前置[《可信命令行》](./01-shell.md)的「故障注入与清理计数」）：区分未映射、权限、内存耗尽和 I/O 失败，分配失败不先破坏旧引用。验收：低 RAM 下 fork+COW 失败只影响目标任务，shell 存活，退出后页数恢复。
- [ ] **epoll 的完整目标语义**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「统一等待与取消约定」、[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」）：逐项补 socket/pipe 等对象的 ET、ONESHOT、重置和关闭引用。验收：边沿通知不反复伪触发，重新 arm 能继续，FD 复用不误投旧事件。
- [ ] **eventfd 计数与关闭**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「统一等待与取消约定」、[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」）：验证计数、semaphore/nonblock、溢出和 epoll 联动。验收：多生产者计数不丢，关闭唤醒按约定执行，不能把它直接等同 Windows 手动事件。
- [ ] **时钟与 timerfd**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「统一等待与取消约定」、[《可信命令行》](./01-shell.md)的「可中断阻塞与重启」）：补 clock_getres、相对/绝对定时与周期到期计数，区分单调钟和实时时钟。验收：校实时时钟不改变单调期限，迟读保留到期次数，无计时器泄漏。
- [ ] **signalfd**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「统一等待与取消约定」、[《可信命令行》](./01-shell.md)的「标准信号帧与备用栈」）：让被屏蔽信号通过 FD 消费，保持线程/进程待决规则。验收：读到正确来源/编号，关闭后信号仍按定义处理，不同时重复消费。
- [ ] **SCM_RIGHTS 描述符传递**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」、[《可信命令行》](./01-shell.md)的「统一等待与取消约定」、[《可信命令行》](./01-shell.md)的「凭据和元数据贯通」）：实现控制消息校验、接收 FD 分配、CLOEXEC 和中途失败回滚。验收：传的是同一打开对象，坏消息/接收表满不泄漏，发送方关闭不使接收对象失效。
- [ ] **有界系统调用与故障观测**（内核机制、用户态组件，前置[《可信命令行》](./01-shell.md)的「明确 ABI 与公共模块边界」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：提供可开关的 trace/故障原因，避免每个高频调用刷串口。验收：缓冲溢出有计数，禁用后低开销，不能读取其他用户秘密参数。
- [ ] **ptrace 与 strace 最小闭环**（内核机制、Linux 接口、用户态组件，前置[《可信命令行》](./01-shell.md)的「标准信号帧与备用栈」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：先 attach/停止/寄存器/系统调用停止，再扩工具需要的请求。验收：strace 可跟踪小程序，非法 tracer 被拒绝，调试器退出不遗留永久停止任务。
- [ ] **全链路大偏移**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」、[《可信命令行》](./01-shell.md)的「完整文件元数据」）：检查 VFS、缓存、后端、stat 和块地址的宽度/溢出。验收：跨 64 MiB、2 GiB 和 4 GiB 边界不截断，错误长度不回绕。
- [ ] **块 I/O 故障与持久化顺序**（内核机制，前置[《可信命令行》](./01-shell.md)的「资源上限的失败行为约定」）：完善队列、超时、刷新/缓存排序与错误传播，复用块后端接口。验收：注入丢中断/读写失败可返回，flush 次序可验证，驱动不永久卡住全部文件操作。

### 第 2 步

- [ ] **文件/目录同步约定**（内核机制、Linux 接口，前置[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」、「块 I/O 故障与持久化顺序」）：区分 fsync/fdatasync、目录项持久化和后端 I/O 错误。验收：写入和 rename 的同步次序能重启验证，刷新失败返回错误，不靠全局同步掩盖目标对象语义。
- [ ] **VMA 与映射生命周期**（内核机制，前置「缺页和 COW 失败安全」、[《可信命令行》](./01-shell.md)的「生命周期与退出取消」）：复核并发 mmap/munmap/mprotect、引用固定和跨 CPU TLB 一致性。验收：一个线程撤销映射时另一个缺页不访问已释放对象，无重叠映射或残留权限。
- [ ] **UNIX 套接字身份与名字**（内核机制、Linux 接口，前置「SCM_RIGHTS 描述符传递」、[《可信命令行》](./01-shell.md)的「公共路径访问检查」、[《可信命令行》](./01-shell.md)的「路径解析约定」）：区分文件路径、抽象名字、peer credentials 和权限。验收：路径节点寿命/相对路径正确，身份不可伪造，未经授权不能连接受限端点。
- [ ] **CPU 与时间统计**（内核机制、Linux 接口，前置「公平调度与 CPU 归属」）：记录用户/内核 CPU 时间、上下文切换，接 wait4/getrusage 和进程统计。验收：busy-loop 与 sleep 明显不同，线程汇总不重复计算。
- [ ] **扩 ext2 工作卷**（内核机制，前置「全链路大偏移」）：以已有 ext2 为短期路线，先支持所选较大块大小和按需块组元数据，保留旧卷。验收：先用 4–8 GiB 测试卷完成读写和重启，不因固定元数据分配失控，不要求先上 64 GiB。
- [ ] **服务生命周期最小版本**（用户态组件，前置[《可信命令行》](./01-shell.md)的「生命周期与退出取消」、[《可信命令行》](./01-shell.md)的「可中断阻塞与重启」、[《可信命令行》](./01-shell.md)的「poll/select 的原子等待」、「有界系统调用与故障观测」）：在现有 init 之上增加或移植 supervisor，支持启动、停止、状态、就绪和退避。验收：一个服务崩溃不结束登录，会重启但不高频循环。

### 第 3 步

- [ ] **文件系统容量与状态**（内核机制、Linux 接口，前置「通用挂载生命周期」、「扩 ext2 工作卷」）：实现 statfs/fstatfs 及安装工具需要的真实可用块/inode/只读状态。验收：写满/删除后计数随之变化，不能把总容量当剩余空间。
- [ ] **基础内存防护**（内核机制、Linux 接口，前置「VMA 与映射生命周期」、[《可信命令行》](./01-shell.md)的「exec 与线程边界」）：验证 NX、页级权限、栈保护页和随机化，审查内核/用户访问边界。验收：只读写入/越界栈/执行禁止页被隔离，不影响其他进程。
- [ ] **匿名共享映射**（内核机制、Linux 接口，前置「VMA 与映射生命周期」）：复用已有共享页对象支持 MAP_SHARED|MAP_ANONYMOUS。验收：fork 后写入互见，单方 unmap 不破坏另一方，MAP_PRIVATE 仍保持 COW。
- [ ] **干净文件页缓存**（内核机制，前置「VMA 与映射生命周期」、[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」）：按文件对象与页偏移共享可丢弃读缓存。验收：两进程读同一文件复用缓存，私有写不污染原页，截断/失效后不会读到旧数据。
- [ ] **core 与用户态 GDB**（内核机制、Linux 接口、用户态组件，前置[《可信命令行》](./01-shell.md)的「标准信号帧与备用栈」、「VMA 与映射生命周期」、[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」、[《可信命令行》](./01-shell.md)的「公共路径访问检查」）：先导出受控 ELF core，再补目标 GDB 路径。验收：能定位用户崩溃堆栈，特权/他人进程的内存不会写入不安全位置。
- [ ] **跨越现有单文件限制**（内核机制，前置「扩 ext2 工作卷」、[《可信命令行》](./01-shell.md)的「打开后删除的寿命」）：扩选定块大小下的文件寻址和回收，先服务小内核/工具产物。验收：256 MiB 非空文件的随机读写、截断、重启校验通过。更大的镜像由《多用户服务系统》的「多 GiB 文件与长期开发卷」单独验收。
- [ ] **多用户会话**（用户态组件、用户态库，前置「登录认证与降权」、[《可信命令行》](./01-shell.md)的「停止/继续与终端作业」、「服务生命周期最小版本」）：接终端/PTY、登录环境、会话退出和用户目录。验收：两个身份同时使用，退出一方不结束另一方，Ctrl-C/终端回收正确。

### 第 4 步

- [ ] **futex 身份与共享等待**（内核机制、Linux 接口，前置「匿名共享映射」、[《可信命令行》](./01-shell.md)的「可中断阻塞与重启」）：PRIVATE 按地址空间与地址匹配，共享 futex 按共享对象与偏移匹配。验收：无关进程同地址不能互唤，同对象不同地址能互唤。
- [ ] **memfd 与 POSIX 共享对象**（内核机制、Linux 接口、用户态库，前置「匿名共享映射」、[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」）：通过 FD 表达共享内存，支持截断、映射和所承诺的 seals，POSIX 命名策略在库/文件系统。验收：跨进程共享、最后关闭回收、禁止的缩放/写入真实失败。
- [ ] **普通文件只读共享映射**（内核机制、Linux 接口，前置「干净文件页缓存」、[《可信命令行》](./01-shell.md)的「公共路径访问检查」）：先交付只读 MAP_SHARED、缓存一致性和截断寿命。验收：同一文件映射与普通读写的可见性符合约定，截断后访问按规则 SIGBUS，关闭 FD 不使映射提前失效。暂不开放可写共享。
- [ ] **可控缓存回收**（内核机制，前置「干净文件页缓存」、「缺页和 COW 失败安全」）：本项先只回收干净页，脏页保持驻留，待「可写共享、脏页与同步」完成后接有界写回。验收：反复读大于内存的只读文件仍可前进，缓存计数升降可观察，回收不死锁、不误丢脏页。
- [ ] **内存与 I/O 统计**（内核机制、Linux 接口，前置「干净文件页缓存」、[《可信命令行》](./01-shell.md)的「定位 I/O 与截断」）：定义 RSS、共享页、缓存、交换和 I/O 计数口径。验收：触页/共享/unmap 计数按定义升降，系统总量与进程量可解释，不全填零。
- [ ] **软件包与文件归属**（用户态组件，前置[《可信命令行》](./01-shell.md)的「链接与目录重命名」、「文件锁」、「文件/目录同步约定」、「文件系统容量与状态」、「跨越现有单文件限制」、[《可信命令行》](./01-shell.md)的「进程和管理操作鉴权」）：先离线清单包，支持安装/卸载、依赖和文件所有者记录。验收：冲突拒绝，卸载不删除其他包文件，失败不留下半安装状态。
- [ ] **原版命令行软件集合**（Linux 接口、用户态组件，前置[《可信命令行》](./01-shell.md)的「停止/继续与终端作业」、「标准线程创建路径」、[《可信命令行》](./01-shell.md)的「rt_sigsuspend 与 shell 的 wait」、[《可信命令行》](./01-shell.md)的「创建、umask 和改属性」、[《可信命令行》](./01-shell.md)的「目录 FD 与 *at 操作」、[《可信命令行》](./01-shell.md)的「管道、FIFO 与挂断」、「匿名共享映射」）：依次运行固定 Bash/coreutils、Git、Python、SQLite。验收：记录未经改源码的二进制、运行库来源和实际行为，不因一次启动成功勾选全部命令。

### 第 5 步

- [ ] **robust futex 与持锁者死亡**（内核机制、Linux 接口，前置「futex 身份与共享等待」、[《可信命令行》](./01-shell.md)的「生命周期与退出取消」）：支持所承诺的 robust list 注册、退出遍历和 owner-death 通知。验收：持锁线程被终止后等待者可恢复或得明确错误，坏用户链表不能死循环或损坏内核，PI 另按目标需求评估。
- [ ] **可写共享、脏页与同步**（内核机制、Linux 接口，前置「普通文件只读共享映射」、「文件/目录同步约定」）：从第一次共享写入就标脏并禁止误回收，接写回及 msync/fsync 错误传播。验收：只读打开 FD 不能建可写共享或用 mprotect 升权，同步后重启内容正确，失败不丢错误或脏页。
- [ ] **OOM 与保留资源**（内核机制，前置「可控缓存回收」、[《可信命令行》](./01-shell.md)的「资源上限的失败行为约定」）：有限重试后拒绝分配或按明示规则终止任务，保留必要管理能力。验收：持续内存压力不使内核停机，选中任务被回收，系统恢复接收新任务。
- [ ] **mremap/madvise 与边界**（内核机制、Linux 接口，前置「匿名共享映射」、「普通文件只读共享映射」）：分步实现目标程序需要的重映射和丢弃建议。验收：移动后内容与共享关系正确，扩展冲突不损坏原区间，不支持的建议明确拒绝。
- [ ] **procfs 进程视图**（内核机制、Linux 接口，前置「CPU 与时间统计」、「内存与 I/O 统计」、[《可信命令行》](./01-shell.md)的「公共路径访问检查」、[《可信命令行》](./01-shell.md)的「描述符与打开文件对象分离」）：补目标范围的 status/maps/fd/exe/cwd 与真实 stat。验收：工具读取跨缓冲边界正确，退出竞争无悬挂对象，跨用户敏感信息受限。
- [ ] **动态链接与系统数据库**（用户态组件、用户态库、Linux 接口，前置「原版命令行软件集合」、「多用户会话」）：固定动态链接器搜索、NSS、locale、时区与账户库行为。验收：dlopen/NSS/Unicode/时间转换各有用例，不依赖构建电脑偶然存在的绝对路径。

### 第 6 步

- [ ] **工具链和开发依赖集合**（用户态组件、用户态库，前置「原版命令行软件集合」、「软件包与文件归属」、「OOM 与保留资源」、「跨越现有单文件限制」）：将工具与库做成独立版本包，补 Clang/链接器等后续构建需求。验收：从干净环境安装后构建两个不同项目，全量/增量/无变化结果合理。基线实测开发 overlay 缺 libpthread 桩库，`-pthread` 链接失败，这一项要把它带上。

## 说明

- 工具链要装得上、用户要能登录使用，所以这一级还要带上最小服务管理、登录会话、离线软件包和通用挂载的基础版本，也就是服务生命周期的最小版本、多用户会话、软件包与文件归属、登录认证与降权、通用挂载生命周期。更完整的服务、网络和包管理在下一份文档里。
- 基线实测 `pthread_create` 返回 EINVAL，在这一级的「标准线程创建路径」解决。自编译的 `cmake -B build -S .` 因为 `utimensat` 未实现在 configure 阶段中断，那个缺口已经由《可信命令行》的「完整文件元数据」补上，这一级把它当作自编译的起点来验收。

## 通过这一级的检查

- [ ] 固定版本的开发工具各自完成一次真实任务：Git 克隆和提交，Python 跑测试脚本，SQLite 的 WAL 与锁，Make、CMake、Ninja 的全量、无变化和改源后增量。
- [ ] pthread 探针通过，`-pthread` 能链接，线程退出、取消和超时竞争之后没有永久挂起。

- [ ] 大偏移读写跨过 64 MiB、2 GiB、4 GiB 边界不截断，块错误和刷新顺序能验证。
- [ ] strace 能跟一个小程序，core 能定位一个用户态崩溃堆栈，并行构建被中断后还能继续开发。
- [ ] 在 Cinux 里从空目录配置并全量构建 Cinux 自己的源码树，得到能启动的镜像，关机重启之后再编一次，无变化时不重编。
