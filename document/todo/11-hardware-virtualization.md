# 11 硬件虚拟化

给 QEMU 一个真正的加速后端，让虚拟机跑得够快。软件模拟和容器都不等这一条。

进入条件：《编译 Linux，运行虚拟机》的 Ubuntu 串口启动和《多用户服务系统》的电源、启动路径之后。

## 要达到的行为

- 能做：一个虚拟 CPU 和客体内存的最小后端，接上中断、时钟和加速接口，和 TCG 做同一客体的功能与性能对照。
- 必须失败得对：非法的客体状态不能破坏 Cinux 的页表和内核内存，客体忙循环不会饿死外层。
- 不能据此宣称：创建一个名为 `/dev/kvm` 的节点等于有了虚拟化，或者开发电脑上的 KVM 能力可以借来当成 Cinux 的实现。

## 任务

同一步里的任务可以按任意顺序做，后一步的任务一定用到前面步骤的成果。每项任务的名字后面括号里先写由谁实现，再写前置。前置是本文档里的任务时直接写名字，是别的文档里的任务时带上那份文档的名字。

### 第 1 步

- [ ] **硬件能力与执行边界**（内核机制、测试与证据，前置[《多用户服务系统》](./03-services.md)的「固件与电源基本路径」、[《基线》](./00-baseline.md)的「冻结并重验起点」）：先选 Intel VMX 或 AMD SVM，核对设备和外层环境是否允许嵌套能力。验收：功能探测与不可用路径明确，不借用开发电脑的 KVM 当 Cinux 能力。

### 第 2 步

- [ ] **单虚拟 CPU 与客体内存**（内核机制，前置「硬件能力与执行边界」、[《原生开发工作站》](./02-workstation.md)的「VMA 与映射生命周期」）：实现最小 vCPU 状态、二级地址转换和退出。验收：受控客体可运行，非法状态不能破坏 Cinux 页表或内核内存。

### 第 3 步

- [ ] **中断、时钟与接口**（内核机制、Linux 接口，前置「单虚拟 CPU 与客体内存」）：接所选加速 API、计时和中断注入。验收：等待/退出可取消，客体忙循环不会饿死外层，接口不是只创建一个 /dev/kvm 名字。

### 第 4 步

- [ ] **QEMU 加速与 Ubuntu 对照**（用户态组件、内核机制，前置「中断、时钟与接口」、[《编译 Linux，运行虚拟机》](./08-linux-and-vms.md)的「raw 磁盘与 Ubuntu 串口」）：接专用 accelerator 或实现明确范围的 KVM ABI。验收：同一客体与 TCG 做功能/性能对照，再扩多 vCPU，不直接承诺通用虚拟化平台。

## 通过检查

- [ ] 受控客体在硬件加速下运行，和 TCG 的结果一致，多虚拟 CPU 之后再单独验。
