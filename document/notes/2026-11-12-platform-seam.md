# 平台设施与驱动之间的缝

状态：已落地（2026-11-12）。记录这层缝管什么、缺什么、端口要补什么。

## 这层管什么

`kernel/platform/` 下六个头，每个都是转发：

| 头 | 管什么 | x86 的实现 |
|----|--------|------------|
| `io.hpp` | 端口与寄存器的读写 | in/out 指令 |
| `ps2.hpp` | PS/2 控制器 | i8042 |
| `bus.hpp` | 总线配置空间与设备发现 | PCI 配置空间 |
| `interrupt.hpp` | 中断申请与投递 | MSI、MSI-X、本地 APIC |
| `clock.hpp` | 定时源 | HPET 与 PIT |
| `firmware.hpp` | 固件表 | ACPI |

驱动只认这六条路径，不再出现 ISA 目录。芯片自己的寄存器偏移、命令序列、
超时算式，留在驱动里，不进接口。

## 契约

有就回答，没有就明确拒绝。驱动已经把这条写进了初始化路径：`find_by_class`
返回空指针就跳过，`init` 返回假就打印一行缺席提示。所以一台没有 PCI 的
机器上，AHCI、NVMe、E1000、xHCI 会安静地不起，而不是编译不过。

## 端口要补什么

| 设施 | x86 现状 | armv7 的对应物 |
|------|----------|----------------|
| 端口访问 | in/out | 没有端口空间，全部走 MMIO |
| PS/2 | i8042 | 多数板子没有 |
| 总线 | PCI | i.MX6ULL 没有 PCI |
| 中断 | MSI 与 IOAPIC | GIC |
| 定时 | HPET 与 PIT | generic timer |
| 固件 | ACPI | 设备树 |

## 还没解决的问题

一是驱动本身的可移植性。16550 与 PS/2 是 x86 的硬件，armv7 的串口是
i.MX 的 UART，触摸也不走 PS/2。接口中立了，驱动不跟着能跑，这一层只解决
"编译不指向 ISA 目录"，不解决"驱动换个芯片还能用"。

二是中断分配这一组最重。现在是 MSI 加 APIC 的转发，armv7 接 GIC 时这组
接口要重写，申请、路由、屏蔽三个动作的语义能对上，机制对不上。

三是总线这组要等真需要时再动。没有 PCI 的机器上它是一个永远返回空的实现，
过度设计没有收益。
