# 串口驱动

## 功能概述

这一页我们把 `kernel/driver/serial` 里的串口驱动走一遍。它管的是 COM1 上那颗 16550 UART（PC 兼容机里最常见的一代串口芯片），全部的家当只有两个文件，露在外面的面孔只有五张：`SerialInit` 负责的是开工，`SerialPutChar` 与 `SerialDrain` 管的是发送和排空，`SerialTryGetChar` 与 `SerialHasKey` 管的则是接收。它是一颗纯轮询的驱动，中断从头到尾都是关着的，发一个字节的时候自己等线，收一个字节的时候自己到状态口去问。它的体量虽小，要紧的却是位置，内核打印链的末端落在它的身上，控制台 tty 取键盘字节时头一个问的也是它，断电前的排空等的还是它。我们顺着寄存器、初始化写表、收发路径、启动早期与控制台接线的次序往下走，沿途的取舍都跟着源码的注释走。

## 寄存器与轮询词表

器件的事实全部待在 `serial.cpp` 的匿名命名空间里，我们把它们一个个认过去。`kCom1Base` 定的是 COM1 的基址 0x3F8，寄存器的门牌靠六个偏移常量认：`kRegData` 是数据口，`kRegIer` 管的是中断允许，`kRegFcr` 管的是 FIFO，`kRegLcr` 定的是线路格式，`kRegMcr` 管的是调制解调器的输出，`kRegLsr` 是行状态的报信口。三个状态位都住在行状态寄存器的身上，收发的两半全靠它报信：`kLsrThre`（0x20）说的是发送保持寄存器空了，`kLsrTemt`（0x40）说的是连移位寄存器在内全都空了，`kLsrDr`（0x01）说的是接收那半边躺着一个没人取走的字节。

数据口与中断允许的两个偏移是一口两用的。按 16550 的惯例，线路控制寄存器的最高位是 DLAB（除数锁存访问位的开关，除数是决定线上波特率的分频值），它竖起来的时候，0 号与 1 号两个口改扮的是除数的低字节与高字节，它落回去的时候，两个口又回到数据与中断允许的本职。这个开关的用法，我们到初始化的一节看写表的原文。

驱动说话用的词安在了 `kernel/driver/base/io.hpp`，我们把这几件词挨个认一遍。`PortWrite` 是端口与值配成的一对记录，`OutB` 的模板版本能把整张写表按次序一口气交出去，`InB` 读回的是一个字节，`WaitBitsSet` 的活是在状态口上打转，等掩码里的位全部亮起才放行，io.cpp 里的实现每转一圈垫一发 `pause`（x86 的暂停指令）。io.hpp 给 `WaitBitsSet` 的注释说它是所有轮询驱动的发送等待，PS/2 那边的 host 层接的也是同一批词，它的 `delay` 槽接的则是 PIT 的微秒等待，那段故事在 [PIT 定时器](pit.md)里讲过了。

## 初始化：一张七行的写表

`SerialInit` 的实现只有一行，把 `kInitSequence` 的整张写表交给了 `OutB`。真正的内容都在表上，我们把七行挨个认过去。头一行给中断允许寄存器写的是 0x00，16550 的四个中断源全部按了下去，这个驱动从头到尾都是不接中断的，线上的仲裁也就省了。第二行写进线路控制的是 0x80，DLAB 竖了起来。跟着的两行借刚才的开关换口，0 号口写进的 0x01 是除数的低字节，1 号口写进的 0x00 是除数的高字节，两个字节合出的除数是 1。第五行写回线路控制的是 0x03，DLAB 落了回去，两个口也恢复了本职，线路的形状在这里定成了 8 个数据位、无校验、1 个停止位，头文件的注释把这句话压缩成了 8N1。第六行写进 FIFO 控制的是 0xC7，使能的位竖起来，收发的两个 FIFO 各清了一遍，接收的触发水位拉到最高的 14 字节。末一行写进调制解调器控制的是 0x0B，DTR（数据终端就绪）与 RTS（请求发送）两根输出抬了起来，OUT2（16550 的通用语义里放行中断线的那根输出）也一起抬了起来。

线的速度是折出来的，除数为 1 的时候，线上走的就是 115200 波特。头文件的注释把整套线路设置归成了 115200 8N1 的线路、开着的 FIFO 与关掉的中断，还给了 `SerialInit` 幂等的评语，说它经得起重复的调用。幂等的性质后面马上有用处，我们到启动的一节会看到两处代码各调它一次。

## 发送、排空与接收

`SerialPutChar` 的两拍很短，我们贴着源码念。头一拍的 `WaitBitsSet` 等的是行状态寄存器上的 THRE 位，发送保持寄存器空了，线才接得下新的字节。第二拍做的事是把字符写进数据口，剩下的搬运归芯片自己的节奏。等待是实打实的忙等，io.cpp 的循环里没有睡眠一说，每一圈里垫一发 `pause`（x86 的暂停指令）。

排空是发送的收尾，`SerialDrain` 等的是另一个位。头文件的注释把两级等待的差别写得清楚：发送等的是保持寄存器，字节出了保持寄存器，也还要在移位寄存器里花掉自己的时间才走完那根线。TEMT 等的是两级全空，等到它的那一刻，打出去的字才算真的离开了机器，注释还说这一口属于断电之前的那一下。控制台的 Flush 调的就是它，断电的调用方我们放到控制台的一节再认。

接收的半边是两张一问一答的面孔。`SerialTryGetChar` 做的事是读行状态寄存器查 DR 位，位没亮的时候答的是 false，出口的参数一个也不碰。位亮了就读数据口，读的动作本身就是消费，字节从此就归了调用者。`SerialHasKey` 管的只是前一半，报的是字节在不在，数据口它是碰都不碰的。注释把接收的姿态写明了：中断在这里是不出场的，调用方得在自己工作的间隙过来轮询。今天定时过来的是控制台 tty，次序我们放到控制台的一节看。

## 启动早期：串口排在引导序列的第一步

引导序列 `kInitSteps` 的表里，serial 这个名字占的是第一行，PMM（物理内存管理器、管物理页的分配和归还）这样的重头角色，都排在它的后面。这一步的实现就是一行 `SerialInit`，它是一个不可能答失败的步骤，RunInitSequence 里失败停机的机关与它无关。串口开得这么早是有讲究的，图的是后面任何一步出事的时候，还有一条说话的路在。我们把这样安排的理由记下，下一节看打印链怎么把它用起来。

这个内核的打印链我们顺着捋一遍。`print::Println` 把参数交给了格式化引擎，结果写进一个 192 字节的栈缓冲，整串字符随后交给了 `console::PutString`，它的 `put_char` 给每个字符发两份，串口与文字屏幕各拿各的份。文字屏幕没就绪的时候，`put_char` 是安静的无操作，screen.hpp 的文件头注释说了这样安排的道理，console 才敢无条件地扇出。次序也是刻意的，console.hpp 给 `InitConsole` 的注释写的是串口在前面，调试不用等一块就绪的屏幕。生产世界的两步分开了走，串口占的是引导序列的第一行，文字屏幕的 init 排在第五步，中间的任何一步真打了失败行，字能走的就只剩串口一条路。ktest 的测试世界（test/kernel/test_main.cpp）把 `SerialInit` 放在了 PMM 的 init 之前，用的想法与生产世界是同一个，屏幕就绪之前的报错行打的就是串口。

引导的世界自带一份一样的表，我们把 boot 的世界也看一眼。boot/early/console.hpp 里躺着同一个 0x3F8 的基址、同一组偏移常量与同一张七行写表，文件头的注释交代了这样复制的缘由：boot 镜像混着 16、32、64 位的代码，它的控制台做成了头内联的形状，每个编译的世界拿自己的一份实例，内核树保留驱动版的控制台，而拷贝本身只归 boot。内核接手的时候，`SerialInit` 把同一组寄存器再编程了一遍，这两次编程做的是同一组写表，`SerialInit` 是幂等的，而做两遍也无妨。

## 控制台与 tty 的接线

console.cpp 是串口今天最大的客户。它的 `put_char` 把字符交给了 `SerialPutChar`，把同样的一份也交给文字屏幕，对外的三张面孔是 `PutChar`、`PutString` 与 `Flush`，进门的时候都持着 IrqGuard 与一把 SpinMutex 的闸。锁立在 console 的一层而不在驱动里，我们把这样安排的道理看一眼：驱动自己是无状态的，谁拿到调用的权力，谁的字节就独占线路，并发的打印穿插不进它的次序。

帧缓冲要接管屏幕的时候，串口的半边照常说话。TextConsole 手里有一个 frame_holders_ 的计数，fb 节点（devfs 里 /dev/fb0 的座位）打开帧就把计数加了上去，最后一个描述符关闭了才减回去。计数非零的时候 `put_char` 直接返回，控制台的笔画全停。`yield_frame` 的注释把这层安排写成了一句，像素安静了下来，串口的那一半照常说话。同一件事 [Canvas 画布](canvas.md)站在帧的一侧讲过了，我们把串口这一侧的口径补在本页里。

`Flush` 是 console 给外界的第三张面孔，实现里持的是闸，调的就是 `SerialDrain`。console.hpp 的注释把这个口子的用途交代了：屏幕的事画完就完了，串口的尾巴字节还留在移位寄存器里，断电这样的终局动作之前要排上一遍，告别行才算真的离开了机器。它今天的调用方是 sys_reboot，关机的路径在 PowerOff 之前调了它。断电前的这最后一口，我们把它当作串口一天工作的收尾。

输入的半边，管消费的是控制台 tty。console_tty.cpp 的取键回调一轮扫三个座位，串口排的是头一个，源码注释给的理由是宿主环境里人是在串口上打字的。随后坐的是 PS/2 键盘，QEMU 的监视器喂它，最后坐的是 USB 键盘。`has_key` 的检查同序，任意一个座位的身上躺着一个字节，它就答真的。取出来的字节进 Tty 的行编辑，回显交回的是 `console::PutChar`，读者没字节可取的时候，让出 CPU 的一手交给调度器的 yield，调度的故事在 [进程与调度器](../proc/process_and_scheduler.md)里讲过了。键盘座位的故事 [键盘驱动](keyboard.md)讲过了，行编辑是 Tty 本体的学问，我们在本页认到取键与回显为止。

## 源码位置

- `kernel/driver/serial/serial.hpp`、`serial.cpp` — 16550 驱动的本体、七行写表与轮询的收发
- `kernel/driver/base/io.hpp`、`io.cpp` — PortWrite、OutB、InB、WaitBitsSet 的轮询词表
- `kernel/init/init_sequence.cpp` — 排在第一行的 serial 步与失败的停机机关
- `kernel/console/console.hpp`、`console.cpp` — 双份的扇出、闸锁、InitConsole 与 Flush
- `kernel/console/screen.hpp`、`screen.cpp` — 文字屏幕的静默、让位与收回
- `kernel/fs/devfs/fb_node.cpp` — 文字屏幕让位与收回的触发方
- `kernel/driver/tty/console_tty.hpp`、`console_tty.cpp` — 三路的取键、回显与让出
- `kernel/boot/print.hpp` — 打印链走到 PutString 的那一截
- `kernel/syscall/sys_reboot.cpp` — 断电之前的 Flush
- `boot/early/console.hpp` — boot 世界的同表拷贝
- `test/kernel/test_main.cpp` — ktest 世界的接线
